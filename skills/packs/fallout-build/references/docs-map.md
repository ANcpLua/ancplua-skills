# Fallout documentation map

Paths are relative to `<examples>/Fallout/docs/`.

Checked on 29 September 2026 against the Fallout source (`version.json` 10.5.0-preview). API names come from a reflection inventory of the compiled assemblies, doubtful page snippets were compiled, and CLI behavior was run. A note that starts with "Source:" marks where a page and the source disagree, and the note is the one to follow. Published packages such as 10.4.0 can differ from this source.

## Gaps

Tasks a build author can reasonably need that no page covers. Each names what the source offers instead.

- Upgrading a build to a newer Fallout: `fallout :update` rewrites the scripts, the build project, the `Fallout.Common` version and `global.json`. Also undocumented: `:trigger` (pushes an empty commit to start CI), `:run`, `:get-configuration`.
- Pinning for reproducible builds: an exact SDK in `global.json`, the `Fallout.Common` version, `packages.lock.json` with locked restore. Pages show only the tool manifest pin and exact `PackageDownload` versions.
- Knowing which APIs exist in the published 10.4.0 package: no page carries a since-version marker.
- Reporting values in the build summary: `ReportSummary(_ => _.AddPair(key, value))` on `FalloutBuild` and `IFalloutBuild`.
- Recording the SHA-256 of an artifact: `GetFileHash` is MD5 only, so use `System.Security.Cryptography`.
- Declaring artifacts and handing them between CI jobs: `.Produces` appears only in CI pages, `.Consumes` nowhere.
- Triggering a GitHub workflow on branches, paths, schedules or manual inputs, or setting permissions, concurrency, fetch depth, timeouts and environments: `OnPushBranches`, `OnPullRequestBranches`, `OnCronSchedule`, `[GitHubActionsInput]`, `WritePermissions`, `ConcurrencyGroup`, `FetchDepth`, `TimeoutMinutes`, `EnvironmentName`, `PublishArtifacts`.
- Keeping a generated workflow by hand: `AutoGenerate = false`, or regenerating on demand with `--generate-configuration`.
- Writing CI config for GitLab, Bitbucket or Jenkins: no generator exists and no page shows a hand-written config. The Bamboo, Bitrise and TravisCI host classes have no page.
- Running AppVeyor, Azure Pipelines or TeamCity on Windows: the generated configs call `build.cmd`, and `fallout :setup` does not create it.
- Running a target inside a container: `.DockerRun(...)` on a target definition. Docker CLI calls appear only in the tool table.
- Splitting work across parallel CI jobs: `[Partition]`, `Partition`, `.Partition(n)`.
- Writing a reusable build extension: `BuildExtensionAttributeBase` with `IOnBuildCreated`, `IOnTargetFailed` and related interfaces. Only the virtual methods on `FalloutBuild` are documented.
- Using the shipped components: `Fallout.Components` (`ICompile`, `ITest`, `IPack`, `IPublish`, `ICreateGitHubRelease`, `IHasGitVersion`).
- Loading secrets from external stores and keeping them out of tool output: `[AzureKeyVaultSecret]`, `[AppVeyorSecret]`, `SetProcessRedactedSecrets`.
- Downloading files and reading changelog release notes: `HttpTasks.HttpDownloadFile`, `ChangelogTasks`.
- Signing packages or binaries: the `AzureSignTool`, `SignTool` and `SignClient` wrappers appear only in the tool table, and the `ISignPackages` component has no page.
- Understanding warnings that no registry lists: `FALLOUT002` (legacy environment variable), `FALLOUT003` (legacy keychain entry) and the extra `FALLOUT001` uses.
