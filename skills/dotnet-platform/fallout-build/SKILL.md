# Fallout builds

Exemplars decide a Fallout build's shape: read them from disk, copy them, and name the exemplar each change follows. `<examples>` is the local examplefalloutbuilds checkout. Read only the reference the task needs:

- [references/exemplars.md](references/exemplars.md): feature-to-exemplar map, ADRs, known breakages.
- [references/pinning.md](references/pinning.md): exact pins for SDK, packages, tools, images, actions.
- [references/docs-map.md](references/docs-map.md): Fallout docs pages and source-checked corrections.
- [references/archcheck.md](references/archcheck.md): running ArchCheck's targets.

## Steps

1. **Inventory** every build project (`*.csproj` referencing `Fallout.Common` or `Nuke.Common`): pins, targets, SDK pin, bootstrap script.
2. **Map** each target and attribute to an exemplar, or say none exists.
3. **Lay out** the exemplar shape: `build/_build.csproj`, `build/Build.cs`, one `build/Build.<Concern>.cs` per concern, `build/Configuration.cs`, import guards; root `global.json`, bootstrap scripts, `.fallout/parameters.json`, `.packageguard/config.json`, workflows generated by `[GitHubActions]`.
4. **Pin** every version per references/pinning.md.
5. **Chain** targets: `.DependsOn` for order, `.Produces` per artifact, `Assert.*` postconditions, `ReportSummary` with path and SHA-256, `[Parameter]`/`[Secret]` inputs, `OnlyWhenStatic`/`OnlyWhenDynamic`.
6. **Prove it** when asked to run the build: two default-target runs from a clean clone pass with locked restore, leave the generated workflow unchanged, and report the same artifact SHA-256.
